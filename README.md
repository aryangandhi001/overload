# Overload

Personal progressive-overload training log. Vanilla JS, no build step, no runtime
dependencies. Data lives in IndexedDB on the device and goes nowhere else.

## Files

| Path | What it is |
|---|---|
| `index.html` | Shell: head, CSS, mount point, script tags. |
| `core.js` | Storage, view router, bottom nav, export envelope, PWA shell. |
| `workout.js` | Progressive-overload log. Depends on core only. |
| `nutrition.js` | Food logging. Depends on core only. |
| `data/foods.json` | 1,649 foods. Built by `scripts/build-food-db.mjs`. |
| `data/portions.json` | Piece weights for raw produce. |
| `data/branded.json` | Packaged products from Open Food Facts. |
| `data/SOURCES.md` | Citations and licence terms. |
| `sw.js` | Service worker: precaches the shell, fires the rest-timer notification. |
| `manifest.webmanifest` | PWA manifest (installable, standalone, portrait). |
| `fonts/` | Barlow Condensed + Inter, latin subset, vendored. No CDN. |
| `icons/` | App icons, generated by `scripts/make-icons.py`. |
| `_original-artifact.html` | The pre-port artifact source, kept as provenance. |
| `scripts/port-to-pwa.py` | Record of the sandbox→PWA port. |
| `scripts/split-modules.py` | Record of the single-file→module split. |
| `scripts/make-icons.py` | Regenerates the icon set. |

## Rebuilding the food data

```sh
node scripts/build-portions.mjs   # USDA piece weights   (once; cached)
node scripts/build-branded.mjs    # Open Food Facts      (re-run to fill 503s)
node scripts/build-food-db.mjs    # assembles data/foods.json
```

## Checks

```sh
node scripts/check-separation.mjs   # workout.js must not reference nutrition
node scripts/check-search.mjs       # the everyday queries resolve correctly
node scripts/check-encoding.mjs     # no stray control characters in source
node scripts/verify-food-db.mjs     # spot-checks the bundle
```

Run all four after touching the modules or the build.

## Running it

A service worker needs a secure origin. `localhost` counts; opening the file
directly with `file://` does **not** — the app still runs from `file://`, but
without offline caching or background notifications.

```sh
cd D:/overload
python -m http.server 8081 --bind 127.0.0.1
# then open http://127.0.0.1:8081/
```

## Updating the app

`index.html` can be edited directly. After changing anything in the precache
list, bump `CACHE` in `sw.js` (`overload-shell-vN`) — that version string is what
tells browsers a new shell exists. The document itself is fetched network-first,
so an HTML-only change lands on the next online load without a bump.

## Storage

One IndexedDB database, `overload`, one object store, `kv`.

| Key | Contents |
|---|---|
| `gym:core` | settings, exercises, routines, PRs, session index |
| `gym:session:<id>` | one full session record |
| `gym:exlog:<exId>` | per-exercise history, newest last |
| `gym:active` | in-progress session, deleted on finish |

Failed writes are retried every 5 s and surfaced as a banner that stays until a
write succeeds. Export from Settings writes `overload-YYYY-MM-DD.json`; import
accepts that file and replaces everything currently stored.
